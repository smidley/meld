## Closest matches

**1. oh-my-symphony** (fork of OpenAI's Symphony) is the closest match on raw vendor breadth: 8 swappable coding-agent backends behind one adapter protocol, git-worktree isolation, live Kanban. What it lacks vs. Meld: agents don't collaborate on the *same* ticket — one agent is picked per ticket/stage, so there is no cross-vendor code review, no merge quorum, and no "last committer's group can't approve" rule. Its coordination substrate is a local Markdown Kanban or Linear/Jira, **not GitHub issues**. It has no evidence/citation requirement, no challenge protocol, no independent auditor, and is explicitly single-host only — no per-vendor orchestrator+PM+worker hierarchy, just flat worker dispatch.

**2. Gas Town + Beads** (Steve Yegge) is the closest match on the "claim lock" primitive — Beads' lease+TTL+heartbeat claim is a more robust version of Meld's "first assignment wins," and Gas Town's Mayor/Polecat/Refinery roles echo Meld's orchestrator/PM/worker split. What it lacks: Beads is explicitly built as **a replacement for GitHub Issues**, not a layer on top of them, so it doesn't get GitHub's native assignment/PR/branch-protection tooling for free the way Meld's design does. No confirmed multi-vendor support (built and documented around Claude Code), no cross-vendor review, no hallucination protection, and the author himself describes it as experimental/"vibe coded."

**3. OpenAI Symphony (upstream)** is the closest first-party match to "an orchestrator that drives tickets to done unattended," including a human-review handoff state. What it lacks: single-vendor (Codex only, by design), Linear (not GitHub issues) as the control plane, no cross-agent review of any kind, and OpenAI has explicitly declined to maintain it as a product going forward — it's offered as a spec/reference for others to fork (which is exactly what oh-my-symphony and several other forks found in this survey did).

**4. Code Conductor** (ryanmac) is the closest match on "GitHub issue assignment as claim lock" specifically — a `conductor:task` label plus GitHub Actions' native credentials is structurally similar to Meld's first-assignment-wins design. What it lacks: single-vendor (Claude Code only), no cross-review, no merge quorum, and it is a small, single-maintainer project (111 stars) with no evidence of production use at the scale Meld targets.

**5. claude-code-review-council + ai-pair** (both Claude Code skills) are the closest match on cross-vendor review specifically: real parallel review of one diff by Claude, Codex/GPT, and Gemini, with claude-code-review-council adding genuine hallucination protection (mandatory file:line citation verification, re-spawning a reviewer with counter-evidence on disputed findings — the closest thing found to Meld's "evidence lines + challenges"). What both lack: they run inside a *single* Claude Code session invoking other vendors' CLIs as subprocesses, not independent per-vendor orchestrators with their own PMs and worker fleets; there is no GitHub issue claim lock, no merge quorum enforced by branch protection, no persistent per-repo negotiation, and the scope is one review event, not an ongoing multi-milestone collaboration. Both are tiny, single-maintainer projects (17 and 338 stars).

No project found combines: independent per-vendor orchestrator+PM+worker "groups," a GitHub coordination issue with a negotiated machine-readable protocol, GitHub-native issue-assignment as the claim lock, cross-*group* (not just cross-model) review with an anti-self-approval rule, a merge quorum, a human plan gate per milestone, and a deterministic "LLM decides / CLI enforces" legality layer, in one system. Meld's combination appears to be novel; the closest individual pieces are scattered across the five projects above.

## Ideas worth borrowing

- **Lease+heartbeat claims, not bare assignment** (Beads): a claim carries a TTL and must be heartbeat-renewed; an expired claim auto-reclaims to `ready`. This is a more crash-resilient version of "first assignment wins" — a Meld worker that dies mid-task shouldn't permanently squat the GitHub issue. [beads.gascity.com/multi-agent](https://beads.gascity.com/multi-agent)
- **A thin, uniform vendor-adapter protocol** (oh-my-symphony's `AgentBackend`): one interface normalizing every CLI's very different session models (Codex's persistent `app-server`, Claude Code's stateless `-p --resume`, Gemini's one-shot calls) into common events (`session_started`, `turn_completed`, `turn_failed`). Directly reusable for adding a third/fourth vendor to Meld beyond Claude Code + Codex without touching the orchestrator. [github.com/cskwork/oh-my-symphony](https://github.com/cskwork/oh-my-symphony)
- **Citation verification before a finding is ever shown** (claude-code-review-council): "every `file:line` opened and checked against actual code before being included in the report" — a concrete, shippable implementation of Meld's "mandatory evidence lines." Its "re-spawn the reviewer with counter-evidence" flow on disputed findings is a workable version of Meld's challenge mechanism. [github.com/yeameen/claude-code-review-council](https://github.com/yeameen/claude-code-review-council)
- **Role-matched review, not redundant review** (ai-pair): assign each vendor's reviewer a *different* concern (one model for bugs/security, another for style/architecture) rather than asking all reviewers the same question — surfaces more distinct issues than three agents duplicating each other. [github.com/axtonliu/ai-pair](https://github.com/axtonliu/ai-pair)
- **"Neutral conclusion" check runs** (Claude Code Review): the AI review's GitHub check run is designed to *never* auto-block merging through branch protection by itself — findings are visible and can be parsed by a human-owned CI gate, but the AI never silently becomes the merge decision. Directly applicable to how Meld's cross-group review should surface without accidentally becoming an unaccountable auto-merge/auto-block. [code.claude.com/docs/en/code-review](https://code.claude.com/docs/en/code-review)
- **A tunable "verification bar" file per repo** (Claude Code's `REVIEW.md`): lets a repo require "behavior claims need a file:line citation in the source, not an inference from naming" as a standing, repo-local policy rather than hard-coding it in the orchestrator. Meld's evidence-line requirement could be made repo-configurable the same way. [code.claude.com/docs/en/code-review](https://code.claude.com/docs/en/code-review)
- **Per-stage agent routing** (oh-my-symphony's `stage_kinds`): different Kanban/milestone stages can be pinned to different agent kinds (e.g., a cheap/fast model for triage, a strong model for build/review). Could inform which vendor's group leads which milestone phase in Meld rather than always splitting work evenly. [github.com/cskwork/oh-my-symphony](https://github.com/cskwork/oh-my-symphony)
- **Vendor-agnostic reviewer backend via LiteLLM** (PR-Agent/Qodo Merge): keeps the review step itself swappable across model providers with one config change — useful if Meld ever needs a reviewer that isn't tied to a full agent CLI. [github.com/The-PR-Agent/pr-agent](https://github.com/The-PR-Agent/pr-agent)
