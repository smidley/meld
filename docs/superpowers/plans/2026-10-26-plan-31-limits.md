# Plan 31 — usage and limits on the page (2026-10-26)

**Goal.** When a provider's usage limit freezes a role, the page says so, in the provider's words, with when it ends and when Meld tries again; and each group's spend in tokens and money is visible beside its budget.

**From the spec.** Section 7 (`LIMITED`), section 22 (what the page may do), plan 9 (freezes).

**What the owner said.** With grok and gemini both frozen on their providers' quotas: "there needs to be a token limit monitor that shows this."

## Decisions (each reversible)

1. **The freeze record carries the provider's words.** `runners.limit_text` reads the last `usage_limit` event's text at freeze time and `_freeze` stores it (capped), so the page quotes the provider rather than guessing.
2. **One arithmetic for when a freeze ends.** `runners.freeze_deadline` is what `_frozen` and the page both use.
3. **Spend from the transcripts, off the request path.** `limits.usage_totals` sums every log through the group's adapter, cached by file size, refreshed by a viewer thread every minute; the state carries the latest snapshot. Providers expose no remaining-quota API from their CLIs, so what Meld can show honestly is what was spent and what the provider said when it stopped.

## Tasks

1. `runners.py` (`limit_text`, `freeze_deadline`, `text` in the record), `limits.py`, `viewer/server.py` (`limits` in the state, `_usage_snapshot`), `app.html`/`app.js`/`app.css` (`#limits`, `renderLimits`); `tests/test_limits.py`, `tests/test_viewer.py`.
2. Spec section 22, `docs/HANDOFF.md`.

`uv run pytest -q` green with no warnings. On the live page with grok and gemini frozen: both lines present with the providers' messages and the next-try times, and the four groups' token and dollar totals.
