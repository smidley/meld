# Plan 32 — `meld`: open it and say what you want built (2026-10-26)

**Goal.** The setup is a minimal number of steps: open Meld in a repository, say what to build, tick which AIs, and it does the rest.

**From the spec.** Section 20 (bootstrap), section 22 (the viewer), plan 30 (App identities).

**What the owner said.** "Next thing to work on is the setup process. It needs to be a minimal step process. A user needs to be able to open meld and tell it what they want built."

## Decisions (each reversible)

1. **The page is the entry.** Bare `meld` is `meld start`: the board when a `.meld.toml` is found, else the viewer in setup mode with a wizard. One surface for setup and for watching. *Not taken:* a terminal prompt sequence (the App step needs a browser anyway).
2. **Three screens, three steps.** What (repository, goal, milestone), who (installed CLIs with login state and default model, pre-ticked when usable), and a progress list: repository set up → each AI's App in two clicks (links the viewer serves) → start. The page polls while the clicks happen in another tab.
3. **Reuse, not rewrite.** `setup.setup` does the repository; `appsetup.AppSetup` does each App; `cli.detach_supervisor` starts a group; the viewer loads a context and becomes the board.
4. **The starter file is PAT-form, converted group by group.** A starter with App fields at zero would not load; each App flow rewrites its own group once installed.

## Tasks

1. `firstrun.py` (`repo_from_remote`, `SetupSession`), `viewer/server.py` (setup mode, `/api/setup`, `/setup/app/<g>/…`, `_adopt_context`), `cli.py` (`start`, bare `meld`, `detach_supervisor`), `appsetup.py` (`suffix`), `app.html`/`app.js`/`app.css` (the wizard); `tests/test_firstrun.py`, `tests/test_viewer.py`, `tests/test_cli.py`.
2. Spec section 20, README, `docs/HANDOFF.md`.
